# Universal player: VK, Spotify, YouTube

Музыкальный плеер и загрузчик для Chrome (Manifest V3). Сейчас полностью
работает ВКонтакте; Spotify и YouTube заявлены в интерфейсе, но ещё не
подключены — источник в сайдбаре показывает их неактивными, а не делает вид,
что они есть.

Что умеет сегодня:

- **Слушать** музыку ВК без открытой вкладки: плеер живёт в offscreen-документе,
  поэтому играет и при закрытом попапе.
- **Навигация как в оригинале**: Главная, Моя музыка (треки и плейлисты), Обзор
  (разделы каталога), Поиск, Радио («Волна»).
- **Эквалайзер** на 10 полос (31 Гц … 16 кГц) с именованными пресетами.
- **Звук**: выравнивание громкости, ночной режим, бас, предусиление, кроссфейд,
  выбор аудиовыхода и системный «Сейчас играет» с обложкой.
- **Монохромный интерфейс**: иерархия строится на типографике и отступах, без
  градиентов и цветных акцентов.
- **Медиа-клавиши** браузера: пуск/пауза, следующий, предыдущий, громче, тише.
- **Скачивание** в максимальном доступном качестве: отдельные треки из любого
  списка или плейлист целиком со страницы. Папки по плейлистам, ID3-теги
  (исполнитель, название, альбом, номер, обложка, текст).
- **Last.fm**: скробблинг с очередью — если Last.fm недоступен, прослушивания
  не теряются.

Всё работает внутри браузера — без нативных программ, ffmpeg и внешних серверов.

## Установка

1. Собрать расширение: `npm install && npm run build`
2. Открой `chrome://extensions`
3. Включи **Режим разработчика** (справа сверху)
4. **Загрузить распакованное расширение** → выбери папку `dist/`
5. Перезагрузи вкладки vk.com, если они были открыты

## Как пользоваться

### Слушать

1. Кликни по иконке расширения → источник **ВКонтакте** должен быть «вошёл»
2. **Главная** / **Моя музыка** / **Радио** → нажми ▶ у трека
3. Плеер внизу: перемотка, громкость, лайк, **очередь** и **EQ**

### Три режима окна

Попап закрывается при клике мимо и тесен для списков, поэтому плеер можно
открыть в отдельном окне (растягивается, живёт поверх) или в боковой панели
Chrome (всегда справа). Кнопки — внизу сайдбара, раскладка одна на все три
режима и подстраивается сама.

### Очередь

Кнопка с точками возле эквалайзера открывает очередь.

- **Перетаскивание** меняет порядок воспроизведения; текущий трек помечен.
- **Перемешать** не уносит играющий трек — он остаётся первым. Выключение
  возвращает исходный порядок: список и порядок воспроизведения хранятся
  отдельно.
- **Повтор**: выключен → вся очередь → один трек.
- На каждой строке списка: **играть следующим** и **в очередь**.
- Клик по треку в очереди переключает на него, крестик убирает.
- Очередь переживает перезапуск плеера.

**Клавиши:** `пробел` — пуск/пауза, `←`/`→` — ±10 с, `Shift+←`/`→` —
предыдущий/следующий, `S` — перемешать, `R` — повтор, `Q` — очередь.

### Звук

Кнопка с волной в плеере открывает панель звука.

- **Выравнивание громкости по LUFS.** Мастера во ВКонтакте различаются больше
  чем на 12 дБ, поэтому плейлист приходится постоянно подкручивать. Плеер
  измеряет громкость каждого трека во время прослушивания и выравнивает до
  −14 LUFS.

  Это **BS.1770 / EBU R128**, а не RMS: K-взвешивание (обрез низа ниже 38 Гц и
  подъём выше 1.5 кГц) приближает измерение к слуху, а двухступенчатый гейт
  выбрасывает тишину и тихие фрагменты — иначе затухание в конце трека занижало
  бы результат. Измерение поканальное: моно-сумма занижала бы трек с перекосом
  в один канал на 3 дБ. Пик считается с передискретизацией ×4 (true peak),
  потому что сэмпловый пик 0 дБFS скрывает межсэмпловые выбросы до +3 дБ.
  Усиление ограничено потолком −1 дБFS.

- **Панель показывает, что измерено**: LUFS, true peak, **DR** (crest factor —
  насколько мастер сжат) и применённую коррекцию. Плюс индикатор `CLIP`, если
  мастер записан с перегрузкой: это свойство записи, а не плеера, и об этом
  честнее сказать, чем молча сглаживать.
- **Спектр** со стерео-разделением: левый канал растёт вверх, правый вниз.
- **Ночной режим.** Мягкая компрессия: тихое слышно, громкое не бьёт. Сила
  регулируется.
- **Бас и предусиление.** Полка на низах до +12 дБ и общий подъём. Последним в
  цепочке стоит лимитер, поэтому клиппинга не будет.
- **Кроссфейд 0–12 с.** Два потока перекрываются по равномощной кривой — без
  провала в середине перехода.
- **Бесшовно внутри альбома.** Альбомы, сведённые как одно целое (живые записи,
  миксы, электроника), не имеют паузы между треками. Режим сшивает их без
  разрыва; между разными альбомами шов остаётся, потому что он там уместен.
- **Режим «по альбому».** Сохраняет разницу между тихой балладой и громким
  открывающим треком — так задумано при мастеринге. Один гейн на весь альбом,
  ограниченный самым громким пиком.
- **ReplayGain в тегах.** Скачанные файлы получают `REPLAYGAIN_TRACK_GAIN` и
  альбомные теги, поэтому звучат ровно так же в foobar2000, MusicBee и Roon.
  Эталон — −18 LUFS, как принято в ReplayGain, а не стриминговые −14.
- **Плеер показывает измеренное**: LUFS, true peak, **DR** (насколько сжат
  мастер), работу лимитера и **моно-совместимость** (корреляцию каналов —
  отрицательная означает, что трек схлопнется в моно).
- **Аудиовыход.** Выбор устройства: колонки, наушники, HDMI.
- **Системный «Сейчас играет».** Название, исполнитель и обложка на экране
  блокировки и в системной панели, перемотка и переключение с гарнитуры.

Громкость и кривая эквалайзера сохраняются: пересоздание плеера (а оно
происходит каждый раз, когда воспроизведение прерывается) больше не возвращает
звук на 100%.

### Скачивать

Два пути, оба ведут в одну очередь:

**Из любого списка** — отметь треки галочками в «Моей музыке», поиске, радио или
обзоре. Появится панель «Выбрано N» с кнопками «Играть», «Скачать», «Снять».
Папкой станет имя из поля «Имя плейлиста» (его подставляет название открытого
плейлиста), иначе — «Загрузки».

Ссылки ВК живут один-два часа, поэтому плеер заранее обновляет ссылки
следующих треков: очередь на вечер не ломается к его середине.

**Со страницы ВКонтакте** — когда нужен плейлист целиком:

1. Открой на vk.com (или vk.ru) страницу нужного плейлиста (или «Моя музыка»)
2. Кликни по иконке расширения → вкладка **Скан** → «Сканировать текущую страницу»
   - расширение само пролистает плейлист до конца и соберёт все треки
   - можно задать своё имя плейлиста, иначе возьмётся со страницы
3. Повтори для всех нужных плейлистов (свои и чужие публичные — без разницы)
4. Вкладка **Плейлисты** → отметь нужные → «Скачать выбранное»
5. Файлы появятся в `Загрузки/VK Music/<Имя плейлиста>/01 Artist - Title.<mp3|ts|aac>`

Трек, встречающийся в нескольких выбранных плейлистах, сохраняется в каждую папку.

## Как это работает

Расширение комбинирует работу через VK API (с Origin-спуфингом через Declarative Net Request) и веб-интерфейс (хук сети и DOM-сборщик):

- **VK API через DNR** — авторизация, каталог, плейлисты, поиск, рекомендации и получение актуальных ссылок на треки (`audio.get`, `audio.getById`) без открытой вкладки
- **Хук fetch/XHR** (MAIN world) — перехватывает ответы веб-плеера на страницах vk.com / vk.ru и извлекает метаданные: исполнитель, название, альбом, обложки, тексты песен, пропуская бинарные аудиопотоки
- **DOM-fallback** — читает современные строки плеера (`[data-testid=MusicTrackRow]` по именованным селекторам названия и исполнителя, игнорируя бейджи и кнопки)
- **Автоскролл** — прокручивает страницу плейлиста, пока не соберёт все треки
- **Service worker** — очередь воспроизведения и персистентность, конвейер загрузок с параллелизмом и retry, сборка и расшифровка HLS (AES-128-CBC), запись ID3v2.4 тегов, сохранение через File System Access или `chrome.downloads`
- **Offscreen document** — Web Audio плеер, нормализация громкости (−14 LUFS), эквалайзер, визуализация спектра и MediaSession

## Ограничения

- **Прокси нужен, если ты вне России**: VK отвечает `wrong origin` на запросы из расширения, поэтому вход возможен только с подменой заголовка `Origin` правилами браузера (DNR) — обычным `fetch` этот заголовок задать нельзя. Вкладка «Сеть» в попапе добавляет свои прокси; в режиме «только VK» через прокси идут лишь домены ВКонтакте, остальной браузер работает напрямую.
- **HLS-форматы**: VK отдаёт треки как HLS. Сегменты бывают ADTS (`.aac`, без ID3 — контейнер не поддерживает тег), MPEG-TS (`.ts`, тег пишется) и прямая ссылка (`.mp3` с тегами). Шифрованные плейлисты `#EXT-X-KEY:METHOD=AES-128` расшифровываются (AES-128-CBC, IV = номер сегмента).
- **Тексты песен** вшиваются, только если они были подгружены во время скана/просмотра.
- **Обложки** берутся из `thumb.photo_*` ответа плеера — они есть не у каждого трека.
- **Ссылки на треки**: при наличии `access_key` загрузчик запрашивает свежий stream URL через API непосредственно перед скачиванием, а при его отсутствии использует захваченный сетевым хуком URL.
- Ссылки VK имеют ограниченный срок жизни — скачивай вскоре после сканирования.
- При больших плейлистах не закрывай вкладку во время сканирования.

## Настройки

- Параллельных загрузок: 1–5
- Пауза между запусками: 100–5000 мс (больше = безопаснее)

## Платформы

Всё платформо-зависимое скрыто за единым интерфейсом (`src/platforms/provider.ts`):

```
src/platforms/
├── provider.ts   # контракт: Track, PlaylistRef, StreamRef, MusicProvider
├── vk.ts         # реализация для ВК (единственная рабочая платформа)
└── registry.ts   # реестр платформ
```

- **ВКонтакте** (`vk.ts`) — полностью реализована и активна.
- **Spotify** и **YouTube** — запланированы на будущее («позже»). В манифесте для них намеренно не запрашиваются host-permissions. В интерфейсе они честно помечены как неактивные до реализации соответствующих SDK и парсеров.

## Разработка

```
npm run dev          # Vite + crxjs (HMR для распакованного dist/)
npm run build        # сборка расширяемого dist/
npm run typecheck    # tsc --noEmit (strict)
npm run lint         # ESLint (flat config)
npm run format       # Prettier (форматирование)
npm run format:check # Prettier (проверка форматирования в CI)
npm test             # Vitest: unit + sw-конвейер + браузерные проверки
```

Для браузерных тестов используется локальный Chromium (переменная `VMF_CHROMIUM_EXE`
или путь по умолчанию из Playwright-кэша); при его отсутствии проверки помечаются skipped.
