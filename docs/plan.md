# План развития

Состояние на v0.16.0: ВКонтакте работает полностью — авторизация и API через Origin-спуфинг DNR, каталог, поиск, рекомендации, скачивание одиночных треков и плейлистов с дешифрованием HLS AES-128 и записью ID3v2.4 тегов, персистентное хранилище на IndexedDB и File System Access API. Очередь и порядок воспроизведения, нормализация звука (-14 LUFS), эквалайзер, MediaSession и Last.fm с оффлайн-очередью реализованы. Полный набор тестов проходит, дерево актуализировано.

Дальше — по приоритету. Spotify и YouTube сюда не входят: строго запланированы на будущее («позже»), сейчас всё внимание на стабильности ВК.

## 1. Уже реализовано (v0.16.0 / Phase 1)

### Очередь и управление плеером

- Модель с разделением _списка треков_ (`queue`) и _порядка воспроизведения_ (`order`), с позицией `pos`.
- Шафл оставляет текущий трек первым; выключение восстанавливает исходный порядок.
- Режимы повтора: `off` / `all` / `one`.
- Действие «Играть следующим» (вставка сразу после текущего слота в `order`).
- Перетаскивание треков (DnD) с пересчётом индексов порядка.
- Персистентность: очередь и состояние воспроизведения переживают перезапуск service worker.

### Звуковой граф (offscreen)

- Web Audio API граф (`AudioContext`, `GainNode`, 10-полосный эквалайзер, `AnalyserNode`).
- Нормализация громкости (−14 LUFS, кэш в метаданных каталога, лимитирование пиков).
- Визуализатор водопада спектра на Canvas.
- Интеграция с `navigator.mediaSession` (метаданные, обложка, синхронизация таймингов, глобальные горячие клавиши).

### Сеть и сборщик

- Официальный и мобильный VK API через Declarative Net Request (DNR Origin-spoofing).
- Сетевой перехватчик fetch/XHR (MAIN world) с фильтрацией бинарных тел и сохранением `access_key`/`restricted`.
- DOM-сборщик по именованным селекторам с устойчивостью к бейджам и кнопкам.
- Поддержка прокси с PAC-маршрутизацией и обработкой 407-челленджей.
- Last.fm скробблер с пакетной отправкой и персистентной очередью.

## 2. Следующие этапы

### 2.1 Три режима окна

Попап закрывается при клике мимо — для долгого прослушивания это неудобно, а 780×600 тесно для списков.

- **Отдельное окно** — растягивается, живёт поверх, не закрывается случайно. То же `popup.html`, но в окне больше не нужен фиксированный размер.
- **Боковая панель** Chrome (`side_panel`) — всегда справа, не теряется.
- **Попап** остаётся для быстрых действий.

Одна адаптивная разметка на три режима.

### 2.2 Кроссфейд и бесшовные переходы

- Два аудио-потока с перекрёстным затуханием 0–12 с.
- Упреждающий резолв stream URL следующего трека до окончания текущего.

### 2.3 Ночной режим и динамическая компрессия

- Компрессор (`DynamicsCompressorNode`) + лимитер: тихое слышно, громкое не режет.
- Регулируемое усиление баса (`lowshelf` фильтр).

## Границы платформ

- **ВКонтакте** — основная и единственная активная платформа на данный момент.
- **Spotify** — отложено («позже»): требует OAuth и Web Playback SDK (звук идёт через SDK, а не по прямому URL). Host-права в манифесте для Spotify намеренно не запрашиваются.
- **YouTube** — отложено («позже»): требует отдельного пайплайна разделения аудио-дорожек и дешифровки подписей. Host-права в манифесте не запрашиваются.
- **zvuk.com** — Widevine DRM, без лицензии на CDM нереализуемо.
