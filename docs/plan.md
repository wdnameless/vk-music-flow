# План развития

Состояние на v0.10.0: ВКонтакте работает полностью — вход без вкладки, каталог,
поиск, радио, плеер без вкладки, эквалайзер, скачивание одним действием и
плейлистом, Last.fm с очередью. 156 тестов, дерево чистое.

Дальше — по приоритету. Spotify и YouTube сюда не входят: сначала доводим ВК.

## 1. Очередь и управление плеером

Сейчас очередь — это плоский список: играет по порядку, ни переставить, ни
перемешать, ни поставить трек следующим.

**Модель**

Разделяем *список* и *порядок воспроизведения*: `queue` — то, что видит
пользователь, `order` — последовательность индексов в этом списке, `pos` —
курсор в `order`.

Почему не перемешивать сам `queue`: перемешивание и перетаскивание — разные
намерения. Если тасовать список, пользователь теряет свой порядок и не может
его вернуть. При `order` выключение шафла возвращает исходный порядок, а
перетаскивание в панели остаётся осмысленным и при включённом шафле.

**Поведение**

| Возможность | Правило |
|---|---|
| Перемешивание | Текущий трек остаётся первым; выключение возвращает исходный порядок |
| Повтор | `off` / всё / один трек |
| Следующим | Вставка сразу после текущего в `order`, а не в конец |
| Перетаскивание | Перестановка в `queue`; `order` пересчитывается переносом индексов |
| Конец очереди | `off` — стоп, `all` — с начала, `one` — трек заново |

**Горячие клавиши** (когда фокус в плеере): пробел, `←`/`→` перемотка,
`Shift+←/→` предыдущий/следующий, `S` шафл, `R` повтор, `Q` панель очереди.

**Готово, когда** очередь видна и управляема, порядок переживает перезапуск
воркера, а перетаскивание и шафл не ломают воспроизведение идущего трека.

## 2. Три режима окна

Попап закрывается при клике мимо — для долгого прослушивания это неудобно, а
780×600 тесно для списков.

- **Отдельное окно** — растягивается, живёт поверх, не закрывается случайно.
  То же `popup.html`, но в окне больше не нужен фиксированный размер.
- **Боковая панель** Chrome (`side_panel`) — всегда справа, не теряется.
- **Попап** остаётся для быстрых действий.

Размеры перестают быть жёстко зашитыми: раскладка тянется, попап ограничивает
себя сам. Одна разметка на три режима — иначе появятся три расходящихся UI.

## 3. Звук

Все узлы проверил в реальном offscreen-документе: `ConvolverNode`,
`DynamicsCompressorNode`, `AnalyserNode`, `StereoPannerNode`, `WaveShaperNode`,
`AudioWorklet`, `setSinkId` — всё доступно, `baseLatency` 10 мс.

### 3.1 Нормализация громкости (первое по эффекту)

Треки ВК разной громкости: старый мастер и современный «кирпич» отличаются до
12 дБ, поэтому в плейлисте приходится крутить громкость.

- Меряем громкость по RMS и пикам, считаем усиление до целевого уровня
  (−14 LUFS как в стримингах).
- Кэш в каталоге по ключу трека — меряем один раз, а не при каждом запуске.
- Применяем `GainNode` в графе перед эквалайзером, с ограничением по пикам чтобы
  не клиппило.
- Варианты: выключено / по треку / по альбому (единый уровень для всего альбома).

### 3.2 Кроссфейд и бесшовные переходы

Два потока с перекрёстным затуханием 0–12 с. Для подборок и миксов — то, что
превращает список в непрерывное прослушивание.

Сложность не в затухании, а в подготовке: ссылки ВК живут недолго, поэтому URL
следующего трека надо резолвить заранее — за время, равное длине кроссфейда.
Первый поток идёт через `GainNode`, второй появляется за секунды до конца.

### 3.3 Ночной режим и усиление баса

- Компрессор + лимитер: тихое слышно, громкое не режет. Основное для тихого
  прослушивания.
- Полка на низах (`lowshelf`) и предусиление — вместе с эквалайзером это
  закрывает «мало баса».
- Отдельная ручка «сила эффекта», а не просто переключатель.

### 3.4 Спектр и индикатор уровня

`AnalyserNode` + `requestAnimationFrame`. Белые полосы на чёрном лягут в нуарный
дизайн: плеер начнёт «дышать». Отдельно — компактный индикатор уровня у обложки,
который виден всегда.

### 3.5 Аудиовыход и системный плеер

- Выбор устройства (`setSinkId`): колонки, наушники, HDMI.
- `MediaSession`: название и обложка на экране блокировки, перемотка из ОС,
  системные «Сейчас играет». Медиа-клавиши уже работают, но система о плеере
  ничего не знает.

## Порядок работ

1. Очередь и управление плеером — влияет на ежедневное использование сильнее всего.
2. Три режима окна — дёшево, снимает главное неудобство попапа.
3. Звук в порядке 3.1 → 3.3 → 3.5 → 3.2 → 3.4: сначала то, что заметно сразу
   и не требует второго потока, потом самое сложное.

## Границы

- Spotify — OAuth и Web Playback SDK: звук идёт через SDK, а не по URL.
- YouTube — отдельные дорожки и шифрованные подписи, другой класс задачи.
- `zvuk.com` — Widevine DRM, без лицензии на CDM нереализуемо.
