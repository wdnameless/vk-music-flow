# План закрытия разрывов VK MUSIC FLOW (gap-plan)

Человекочитаемый план. Технические детали — в `interfaces.md` и `tasks.md`.

## Куда идём и зачем

Доводим ВК-ядро до состояния «ничего не врёт и не роняет»: виды грузят данные,
ошибки видны там, где случились, очередь переживает рестарт воркера, сеть
восстанавливается после капчи/407/протухшего токена, доки и релизная гигиена
соответствуют коду. Объём — 5 вертикальных срезов, каждый независимо проверяем.

## Срезы (вертикальные, в порядке ценности)

1. **S1 UI-честность** — виды «Моя музыка»/«Радио» грузят дефолтные списки;
   чипы «Волна»/«Рекомендации» различаются и подсвечиваются; ошибки плеера и
   очереди показываются в текущем виде; `#homeHero` без дублей слушателей;
   лайк/дизлайк отражают и переключают состояние трека.
2. **S2 Очередь и рендер панели** — удаленая/кликнутая строка маппится через
   `data-qi` (строгость: вместо строгого маппинга с дропом простая сериализация
   клика); панель не перерисовывается таймером под пальцами; водопад сдвигается
   без диагонального среза.
3. **S3 Сеть и авторизация** — `vkCall` восстанавливает токен при 5 после
   любого ретрая, обрабатывает 14/17; прокси-авторизация сверяется с
   `challenger`, ограничена счётчиком 407, `checkProxy` различает 407/502;
   блок артистов — по целым токенам, а не подстроке.
4. **S4 Плеер и загрузки** — состояние очереди сохраняется из каждой точки
   входа; скроббл не дублируется после рестарта SW; пакетная запись в журнал —
   одна; HLS с посегментными ретраями; `saveBlob` без двойного держания трека;
   вывод звука/таймеры/медиасессия/громкость/парсинг/теги — по строкам манифеста.
5. **S5 Сбор, доки, гигиена** — сборщик устойчив к бейджам, встроенным
   структурам, `access_key`/`restricted`, бинарным телам; `docs/plan.md` и
   README отражают v0.16.0; CI/игнор/артефакты прибраны; маркировка
   Spotify/YouTube честная и явная.

## Границы (явно НЕ входит)

- Реализация Spotify и YouTube (только честная маркировка, R36).
- Новый дизайн и новые фичи поверх закрытых разрывов.
- Интерактивное восстановление 2FA/капчи сверх кодов 14/17.

## Критерии готовности среза

Зелёные `typecheck + lint + test + build`, регрессионный тест на каждое
исправленное поведение (падает без фикса), дымовая проверка пути в браузере.

## Риски

- Живые методы VK меняются без предупреждения: `vknext-recon.md` фиксирует
  измеренное, код не должен врать о неподтверждённом.
- Ограниченные треки (`content_restricted` 2/3) неиграбельны терминально —
  это не чинится, только объясняется в UI (уже есть).
